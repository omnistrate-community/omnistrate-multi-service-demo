Omnistrate reference architecture

Durable AI Platform

A managed Cassandra offering, driven by a Kubernetes operator with its own backup and restore workflows, feeding a second offering that runs Temporal, vLLM and Trino on infrastructure provisioned by Terraform. Both deploy into the customer's own AWS, GCP or Azure account.

How to read it

The operator plan

A K8ssandraCluster custom resource reconciled by the k8ssandra operator, with create, scale, stop, start, backup, restore, repair and node recovery all exposed as instance actions a customer can invoke.

Terraform

Four internal resources per cloud, attaching to the network the deployment cell already created. The output key names are identical across all three clouds, which is what lets the Helm layer above them stay cloud-agnostic.

Helm

Five releases in dependency order: the schema job runs first and creates the Cassandra keyspace and the SQL visibility schema, then the Temporal server, vLLM, the workers and Trino follow.

GPU and credentials

vLLM serves a Qwen model whose weights are streamed from the provisioned bucket. Federated identity covers credentials everywhere except Medusa on Azure, which still needs a static storage key.

Design notes

Split persistence

Cassandra holds Temporal's history and shards, since Temporal writes a row per state transition rather than per workflow. A managed Postgres holds the searchable visibility index and the database behind Trino's Iceberg catalog.

Composition

The customer creates a Cassandra instance, then supplies its endpoint and password when creating the platform instance. Managed Cassandra stands on its own, so a customer who wants only a cluster can subscribe to just that.

Reachability

Instances in the same deployment cell share a cluster and a cell-wide DNS zone, so the platform reaches Cassandra over ordinary in-cluster CQL. Creating both against the same VPC makes that independent of cell placement.

Where Azure differs

Medusa backups on Azure use a storage account key, the only long-lived credential here, where AWS and GCP use federated identity with nothing stored. Azure also wants btree_gin added to azure.extensions before Temporal's visibility schema applies.
